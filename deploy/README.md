# Развёртывание dcm4chee с новым интерфейсом

Комплект ставит на сервер всё, что нужно для работы архива снимков:

| Часть | Что делает |
|---|---|
| **Архив** (dcm4chee-arc 5.35) | принимает и отдаёт снимки по DICOM и DICOMweb |
| **PostgreSQL** | индекс: пациенты, исследования, серии |
| **OpenLDAP** | конфигурация: AE-титлы, устройства, правила |
| **Интерфейс** | новый веб-интерфейс: поиск, просмотр, настройка |

Проверено на **Ubuntu 22.04 / 24.04** и **Debian 12**. Работает через Docker или Podman.

> Комплект рассчитан на **внутреннюю сеть клиники**: входа по логину пока нет. Не открывайте
> порты сервера в интернет. Авторизация появится отдельным этапом и ляжет поверх без переустановки.

## Что нужно от сервера

- 2 ядра, **4 ГБ памяти** (лучше 8), 20 ГБ под систему — и сколько угодно под снимки
- Ubuntu или Debian с доступом в интернет — или [офлайн-пакет](#закрытый-контур-без-интернета)
- Свободные порты: 80 (интерфейс), 8080 (DICOMweb), 11112 (DICOM), 2575 (HL7)

## Установка

```sh
git clone <адрес репозитория> dcm4chee
cd dcm4chee/deploy
sudo ./install.sh --install-runtime
```

`--install-runtime` поставит Docker, если его нет. Через 3–5 минут скрипт напечатает адреса:

```
Готово.

  Интерфейс        http://10.0.0.15/
  DICOM            AE Title DCM4CHEE, 10.0.0.15:11112
  DICOMweb         http://10.0.0.15:8080/dcm4chee-arc/aets/DCM4CHEE/rs
  Штатный UI       http://10.0.0.15:8080/dcm4chee-arc/ui2/
  Данные           /var/lib/dcm4chee
```

Повторный запуск `install.sh` безопасен: настройки, пароли и данные не меняются.

### Полезные параметры

| Параметр | Зачем |
|---|---|
| `--data-dir /data/pacs` | хранить данные на отдельном диске (по умолчанию `/var/lib/dcm4chee`) |
| `--host 10.0.0.15` | адрес, который увидят модальности, если определился не тот |
| `--set DICOM_PORT=104` | любая настройка из `.env` — здесь стандартный порт DICOM |
| `--runtime podman` | Podman вместо Docker |
| `--ui-only --archive-url http://pacs:8080` | только интерфейс к уже работающему dcm4chee |

## Подключить модальность или другой PACS

**Чтобы аппарат отправлял снимки в архив**, укажите в его настройках:
AE Title `DCM4CHEE`, адрес сервера, порт `11112`.

**Чтобы архив мог отправлять снимки аппарату или другому PACS**, заведите узел в интерфейсе:
*Конфигурация → + Новое подключение*. После сохранения нажмите «Применить».

## Повседневное

```sh
./dcm4chee.sh status        # что запущено, сколько исследований, сколько места
./dcm4chee.sh logs arc      # журнал архива (ldap, db, ui — остальные части)
./dcm4chee.sh stop          # остановить
./dcm4chee.sh start         # запустить
```

После перезагрузки сервера всё поднимается само.

## Резервное копирование

```sh
sudo ./dcm4chee.sh backup                         # в deploy/backups/<дата>
sudo ./dcm4chee.sh backup /mnt/nas/pacs-backup    # в свой каталог
```

В копию попадают база, конфигурация (LDAP) и `.env` с паролями — всё, без чего архив
не восстановить. **Снимки** по умолчанию не копируются: их объём бывает огромным, и обычно
их копируют средствами хранилища (`rsync` каталога `<данные>/storage`, снапшоты диска).
Скопировать вместе со снимками: `backup --with-storage`.

Копию стоит делать по расписанию, например ежедневно из cron:

```
0 2 * * * cd /opt/dcm4chee/deploy && ./dcm4chee.sh backup /mnt/nas/pacs-backup/$(date +\%u)
```

(семь каталогов по дням недели — неделя истории).

## Восстановление

**На том же сервере** — откатить базу и конфигурацию к копии:

```sh
sudo ./dcm4chee.sh restore deploy/backups/20261015-020000
```

**На новом сервере** (переезд или авария):

```sh
cd dcm4chee/deploy
cp /путь/к/копии/env .env                 # те же пароли — иначе копия не встанет
sudo ./install.sh --install-runtime        # поднимет пустой архив с этими паролями
sudo ./dcm4chee.sh restore /путь/к/копии
```

Снимки: либо копия была сделана с `--with-storage`, либо верните каталог `storage` на место
до запуска `restore`.

## Обновление

Версии записаны в `.env` (`ARC_VERSION`, `LDAP_VERSION`, `POSTGRES_VERSION`). Чтобы обновиться:

1. `sudo ./dcm4chee.sh backup`
2. Поменяйте версии в `.env` на новые из [официального compose](https://github.com/dcm4che-dockerfiles/dcm4chee-arc-psql/blob/master/docker-compose.yml)
3. `sudo ./dcm4chee.sh update`

Исправления внутри одной версии (5.35.1 → 5.35.2) ставятся сразу. При переходе на новую
версию (5.35 → 5.36) скрипт остановится: между такими версиями бывают изменения структуры
базы — проверьте [заметки к выпуску](https://github.com/dcm4che/dcm4chee-arc-light/releases)
и запустите `update --force`.

Новый интерфейс обновляется тем же `update`, если рядом лежит репозиторий с исходниками.

## Podman

```sh
sudo apt install podman podman-compose
sudo ./install.sh --runtime podman
```

Без `sudo` Podman работает от обычного пользователя, но не может занять порт ниже 1024 —
интерфейс тогда окажется на порту 8000 (скрипт сообщит). Данные в этом случае укажите
в домашнем каталоге: `--data-dir ~/dcm4chee-data`.

## Закрытый контур (без интернета)

На машине с интернетом соберите пакет — образы и скрипты одним архивом:

```sh
./package-offline.sh                 # для обычных серверов (x86_64)
./package-offline.sh --arch arm64    # для ARM-серверов
```

Перенесите `dcm4chee-offline-*.tar.gz` на сервер и:

```sh
tar xzf dcm4chee-offline-*.tar.gz
cd dcm4chee-offline/deploy
sudo ./install.sh
```

Docker на сервере должен уже стоять (или ставиться из локального зеркала пакетов).

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `заняты порты: 80` | на сервере уже есть веб-сервер: `--set UI_PORT=8000` или освободите порт |
| `архив не ответил за 15 мин.` | `./dcm4chee.sh logs arc` — чаще всего не хватает памяти; уменьшите `JVM_HEAP_MAX` в `.env` или добавьте памяти |
| Модальность не может отправить снимки | проверьте порт 11112 в файрволе: `sudo ufw allow from 10.0.0.0/8 to any port 11112` |
| Нужна функция, которой ещё нет в новом интерфейсе | штатный интерфейс работает: `http://<сервер>:8080/dcm4chee-arc/ui2/` |

## Где что лежит

```
deploy/
├── install.sh          установка
├── dcm4chee.sh         сопровождение
├── compose.yaml        состав: ldap, db, arc, ui
├── .env                настройки и пароли (создаёт install.sh, только для владельца)
└── backups/            резервные копии по умолчанию
<данные>/               по умолчанию /var/lib/dcm4chee
├── db/                 PostgreSQL
├── ldap/, slapd.d/     конфигурация
├── wildfly/            сервер приложений архива
└── storage/            снимки
```
